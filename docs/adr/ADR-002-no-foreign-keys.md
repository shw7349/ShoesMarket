# ADR-002 테이블 간 FK 제약 대신 인덱스 + 애플리케이션 무결성

- 상태: 채택
- 영역: 인프라
- 결정일: 2026-11-05

## 배경
드롭 순간 대량의 INSERT/UPDATE가 몰린다. FK 제약은 쓰기마다 참조 무결성 검사를 유발해 경합과 락 범위를 키운다.

## 결정
테이블 간 FK는 걸지 않고 인덱스로만 조회를 보조한다. 무결성은 애플리케이션과 핵심 유니크 제약으로 지킨다. 특히 `reservation(drop_id, user_id)` 유니크 키는 Redis가 뚫렸을 때의 최후 방어선이다.

## 트레이드오프
DB 차원의 참조 무결성 보장을 포기한다. 대신 잘못된 참조가 생기지 않도록 도메인 로직과 테스트로 막고, 정합성 배치로 사후 검증한다.

## 검증
정합성 배치(`StockConsistencyService`)가 `total == CONFIRMED + RESERVED + Redis 남은재고`를 대조해 불일치를 기록한다.
