# ADR-001 재고 선점 기본 전략으로 Redis Lua 사용

- 상태: 채택
- 영역: 재고
- 결정일: 2026-11-05

## 배경
한정 수량을 동시에 수만 명이 사려 할 때 초과판매를 막아야 한다. 핵심은 "재고 확인 + 1인 제한 검사 + 차감"이 하나의 원자 단위여야 한다는 것.

## 고려한 선택지
- DB 비관적 락(SELECT FOR UPDATE): 정확하지만 재고 행이 직렬화 지점이 되어 처리량이 떨어진다.
- DB 낙관적 락(@Version + 재시도): 경합이 심하면 재시도가 폭증한다.
- Redisson 분산 락: 다중 인스턴스엔 유효하나 락 획득/해제 왕복 비용이 든다.
- Redis Lua 스크립트: 토큰 확인·1인 제한·차감을 한 번의 EVAL로 Redis 단일 스레드에서 처리한다.

## 결정
기본 전략은 Lua로 둔다. 비교용으로 나머지 세 구현도 `StockReserver` 인터페이스로 두고 설정값으로 교체 가능하게 한다.

## 트레이드오프
Redis에 강하게 의존하고 스크립트를 관리해야 한다. Redis 장애 시 선점 경로가 멈추므로, DB를 진실의 원천으로 두고 재시작 시 재고를 복구하는 절차를 마련했다(README 참고).

## 검증
재고 100 / 유저 1000 동시 선점 → 정확히 100건, 재고 0 통합 테스트로 초과판매 0을 확인한다. 방식별 처리량은 k6로 비교한다(docs/load-test-result.md).
