# ADR-003 대기열에 Redis Sorted Set + 입장 토큰 사용

- 상태: 채택
- 영역: 대기열
- 결정일: 2026-11-05

## 배경
오픈 순간의 트래픽을 그대로 선점/결제로 흘려보내면 뒤 단계가 무너진다. 입장 속도를 제어할 장치가 필요하다.

## 고려한 선택지
- DB 큐 테이블: 순번 계산과 폴링이 DB 부하로 직결된다.
- Redis List: 순번(rank) 조회가 불편하다.
- Redis Sorted Set: score에 진입 시각을 넣어 순번을 `ZRANK`로 얻고, 입장은 `ZPOPMIN`으로 상위 N명을 뽑는다.

## 결정
대기열은 Sorted Set으로 두고, 진입은 `ZADD NX`(동일 유저 중복 방지), 입장 스케줄러가 1초마다 상위 N명을 꺼내 입장 토큰을 발급한다. 선점은 이 토큰이 있어야 가능하다. 초당 입장 인원(admit-per-second)으로 뒤 단계 부하를 조절한다.

## 트레이드오프
입장 속도를 올리면 대기 시간은 줄지만 선점/결제 경로의 순간 부하가 커진다. 적정값은 부하 테스트로 정한다.

## 검증
중복 진입 → AlreadyInQueue, 진입 순서대로 순번, 입장 스케줄러가 상위 N명에게 토큰 발급을 통합 테스트로 확인한다. admit-per-second 50/100/300 비교는 k6로 측정한다.
